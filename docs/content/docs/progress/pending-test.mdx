# Pending Tests

The current release needs manual verification in these areas:

- Brand name: the home hero should be uppercase `JTCANVAS`, the tagline highlight should say Infinite Canvas, and the public top nav should stay 「景甜画布」 / Jingtian Canvas. The canvas library page should show only the heading Canvas library with no eyebrow label; new canvases should be named Canvas 1, Canvas 2 (not Jingtian Canvas 1). The browser tab and admin header still follow Site name and must not change the home hero, tagline, or public top nav.

- Canvas blank-area create menu: right-clicking empty canvas should open a compact Create node menu listing every currently addable node without scrolling; choosing an item should create that node at the click position. Double-clicking empty canvas should no longer open this menu. Right-clicking a node or connection should still open the existing action menu, and the browser context menu should not appear.

- Admin Services: `/admin/services` should list Image generation, Video generation and Agent, all on by default. Turning video off must hide 视频创作台 / Video Studio in the header, redirect `/video` to the canvas, hide the canvas bottom-toolbar video button and existing video nodes, and make `POST /api/generations` with capability `video` return 403 `视频生成服务已关闭`. Image generation behaves the same. Turning Agent off must hide the home and canvas Agent button, Codex status and connect panel; turning it back on restores them. Saving Site settings must not reset these switches. The audit log should record `settings.services`.

- Admin Users: `/admin/users` should support row selection and Delete selected. The current admin account cannot be checked. Deleting the last remaining admin, a user with frozen balance, or a user with a pending/running generation must fail with a clear error. Successful delete removes that user's canvases, files, generation records and ledger, and writes `user.delete` to the audit log.

- Admin Redeem cards: `/admin/cards` should have a Filter button for batch name, row selection, and batch delete. Inside a batch, cards can be filtered by status, multi-selected, voided if unused, or deleted. Redeemed ledger rows stay.

- Admin Transactions: the Ledger tab should filter by type, search username or note, and export the current filtered set as CSV.

- Admin Generations: `/admin/tasks` should filter by type and status, search username/model/error, and export the filtered set as CSV.

- Admin dashboard reconciliation: a mismatch banner should appear only when wallets disagree, can be dismissed for the session, and View details should list usernames with expected vs actual amounts. A clean run should not show a persistent success banner.

- Admin Storage info alert: “Switching only affects new files…” should use a black background with white text in light theme, and remain readable in dark theme.

- Add to My Assets: clicking Add to My Assets / Save asset from Image Studio, Video Studio, or the canvas should succeed and show the item on `/assets` after refresh. `POST /api/assets` must not return 400 for unknown fields such as `coverUrl` or `data`.

## Commercialisation (the largest change in this release)

The project moved from browser-local and browser-direct to a server-authoritative model with a login wall and metered billing. Almost every path changed, so the whole flow is worth walking through.

- Accounts and access: the entire app requires a sign-in except the homepage; login and registration share a homepage dialog with a small-radius rectangular sliding toggle; the first registered account becomes the administrator; new users start at zero balance and cannot generate until they top up; changing a password or being disabled by an admin revokes every session immediately; the top navigation shows the current balance and opens a narrow My wallet drawer (also on the canvas). There is no Account nav item. Preferences open as a wider right-hand drawer. The frontend header no longer links to admin; administrators open `/admin` by URL, and non-admins are rejected.
- Balance and billing: every Generate button shows a live estimate that tracks count, size and duration; an insufficient balance disables the button and the server rejects the request with 402; images bill per image and video per second with optional per-size-tier prices; submitting reserves funds, success settles against actual output and returns the remainder, and failure refunds in full; a double submit must not charge twice; a per-user concurrent task cap applies; redeem cards credit exactly once even under concurrent redemption.
- Cloud data: canvases, assets and generated files all live on the server and follow the account across devices; canvas saves are per project and panning does not write to the server; concurrent edits of one canvas produce a version conflict rather than a silent overwrite; ZIP import re-uploads files under fresh storage keys; the account page offers a one-time import of leftover browser-local data. Local `npm run dev` without nginx should still display generated images from `/api/files`, not a 0-byte empty response.
- Admin area: `/admin` uses a left-sidebar SaaS layout with dashboard, users, generations, transactions, redeem cards, channels, pricing, PiAPI pool, storage, services, site settings, audit log and API docs. The top bar should use a light background and dark title/username in light theme, and clicking the username must not navigate away. Back to app sits next to the username; the sider has no collapse control. A short viewport must let the sider menu scroll to API docs. Provider keys and S3 secrets are never returned in plaintext, models without a price are hidden from users, reconciliation reports mismatches without changing data (dashboard banner is closable and lists the wallets), and every privileged mutation is audited. The public `/api/docs` Swagger UI is gone; API docs live under `/admin/docs`. PiAPI is auto-seeded on API start only when the catalog is empty; the pool page can create the channel but will not rewrite an admin-owned model list. Image generation defaults to Seedream 5 Pro 宽松 when the user has not picked a model.
- Removed from the frontend: provider channels, the model script editor, the WebDAV panel, the local-storage panel and the `/piapi` page. No third-party API key exists in the browser any more, and the `?baseUrl=` / `?apiKey=` URL injection is gone.
